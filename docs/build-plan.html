Technical blueprint · automated plan mirroring

Mirror the walls, re‑set the type

A flip is one line of OpenCV. The whole engineering problem is the text: find every string, erase it, mirror the drawing, then re-render the same characters unreflected at the mirrored anchor — with the drafting conventions that make 5155 still read bottom-to-top after it moves from the right edge to the left.

RECOMMENDATION 1

Route by input type first

If the plan exists as vector PDF or SVG — and CAD-exported plans usually do — mirror the page transform and counter-flip each text matrix. Lossless, no OCR, no inpainting, ~200 lines. Build this before touching computer vision.

RECOMMENDATION 2

Standalone Python for the raster path

OpenCV, RapidOCR and Pillow do the work; PySide6 supplies the review canvas. Photoshop UXP has no OCR runtime and Revit cannot see inside a PNG at all.

RECOMMENDATION 3

Ship a review step, not an oracle

OCR will mangle Køkken and Vær. some of the time. A 20-second correction pass beats a 40-minute Photoshop retype and is the difference between a demo and a tool the team trusts.

01 · framing

You are not mirroring an image. You are re-typesetting an annotated drawing.

Every design decision below follows from that sentence, and from one more observation: a raster plan is a drawing that has already lost information the tool then has to guess back.

The sample unit plan carries three classes of mark, and each behaves differently under reflection:

  • Geometry — poché walls, door swings, the kitchen run, the WC fixtures. Reflection is correct and complete. A door that swung right now swings left, which is exactly what a mirrored unit does.
  • Annotation glyphs — Køkken, Stue, Vær. 1, Bad, Toilet, Entre, and the millimetre dimensions 4045, 3200, 5155, 2105, 870. Reflection is wrong. Only their anchor points should move.
  • Orientation-bearing symbols — a north arrow, a scale bar, a title block, a stair direction arrow, a company logo. Reflection is actively harmful: a mirrored north arrow is a false statement about the building. These must be detected and excluded, then pasted back unmirrored at a mirrored anchor.

The third class is the one hand-mirroring in Photoshop also gets wrong, and it is worth designing for from day one even though the sample plan happens to contain none.

The information-loss ladder

Accuracy is decided by what format reaches the tool, not by how clever the algorithm is. Route accordingly:

InputWhat survivesText fidelityRoute
Revit / DWG modelReal text entities, styles, dimension objectsExactMirror natively upstream — no tool needed
Vector PDF, SVG, AIGlyph runs, transform matrices, embedded fontsExactRoute A — matrix counter-flip
300 dpi PNG / TIFFPixels only; strings must be inferred98–99% charsRoute B — CV + OCR + re-render

Ask where the PNGs come from before writing any OpenCV

If the team's PNGs are exported from Revit or a PDF that still exists on the server, Route A alone eliminates the manual work at 100% fidelity, and the CV pipeline becomes a fallback for client-supplied images rather than the main product. That single question can cut this project in half.

02 · mechanism

Two routes, one output contract

Both paths emit the same pair of files: the mirrored drawing and a JSON sidecar recording every text placement, its source string, and its confidence. The sidecar is what makes the result auditable and re-editable.

Why Revit is the wrong instrument, precisely

Revit's ElementTransformUtils.MirrorElements already keeps TextNote and Dimension elements readable — mirroring in Revit is not a problem anyone needs to solve. An add-in only helps if the input is a model, and the input here is a flattened image. Bridging that gap means raster-to-vector conversion plus semantic wall recognition: a research project an order of magnitude larger than the one being scoped, and one whose output an architect would have to verify line by line anyway.

Keep it on the roadmap only as an upstream fix: if the plans originate in Revit, publish mirrored unit types from the model and the whole raster pipeline becomes unnecessary for that source.

Why UXP is the right second phase, not the first

UXP's value is not the algorithm, it is the handoff. A panel that receives placement JSON and creates genuine Photoshop text layers gives the team a PSD they can keep tuning — the exact thing a flattened PNG denies them. But UXP cannot run the detection itself, so it needs the Python core to exist first, reachable over http://127.0.0.1:8731. Build the brain, then bolt on the face.

One dependency choice worth making early

PaddleOCR has the best out-of-the-box Latin accuracy but drags in paddlepaddle, which is painful to freeze on Windows. RapidOCR-ONNXRuntime ships the same PP-OCR models as ~50 MB of ONNX, installs cleanly, and packages with PyInstaller. Develop against RapidOCR; keep a PaddleOCR adapter behind the same interface for accuracy comparisons.

04 · core processing

Route B in seven stages

Each stage is independently testable and writes its intermediate to disk under --debug, because the failure you cannot see is the one that costs a day.

S1

Normalise the input

Deskew, then guarantee enough resolution for OCR. Measure median glyph cap-height from connected components; if it is under 14 px, upscale 2× with Lanczos and carry the scale factor through the whole pipeline so the final render happens at the higher resolution and downsamples once at export.

  • Deskew by minimising the variance of horizontal projection profiles over ±3°, or from the dominant Hough line angle — CAD exports are usually already square, so cap the correction and log it.
  • Binarise with Otsu for the mask, but keep the original in colour: the render stage needs the true ink and paper values.
opencv-pythonnumpyPillow
S2

Detect and read every text run

Run OCR detection three times — on the image, and on it rotated +90° and −90° — then map every quad back to source coordinates and keep the highest-confidence claim per region. Recognition models are trained on horizontal lines and read rotated dimension text badly; the triple pass is what makes 5155 and 2105 reliable.

  • Second pass for numerics only, with a digit-plus-comma whitelist, over boxes whose text matches ^[\d.,lOoISB]+$. This kills the classic 5155 → 5l55 and 870 → 87O substitutions.
  • Merge overlapping detections with NMS at IoU 0.3, then classify each run: room label (alphabetic, largest cap-height, centroid inside a room polygon), dimension (numeric, adjacent to a long thin line), annotation (short, mixed — H*, WC), excluded (inside a registered title-block or north-arrow region).
  • Room polygons come free: invert the binary image, remove components thinner than the wall thickness, and label the enclosed white regions.
rapidocr-onnxruntimepytesseract (dan)scipy.ndimage
S3

Correct against a domain lexicon

Danish plan vocabulary is a closed set of maybe sixty words. Fuzzy-match every alphabetic run against it and snap when the edit distance is 1 or 2, restoring the diacritics OCR almost always drops.

  • Seed list: Stue, Køkken, Værelse, Vær., Bad, Toilet, Entré, Bryggers, Gang, Repos, Altan, Terrasse, Depot, Skab, Garderobe, Teknik, Loft, Kælder, Soveværelse, Opholdsrum.
  • Kokken → Køkken at distance 1; Vaer. 1 → Vær. 1; 5tue → Stue. Every snap is recorded in the sidecar with the raw OCR string beside it, so the review pane can show what changed.
  • Dimensions get a plausibility check instead: 3–5 digits, 200–20000 mm, and — where two dimensions bracket the same wall run — a sum consistency warning.
rapidfuzzunicodedata
S4

Fit the type style

To re-render invisibly you need four numbers per run, all measurable from the crop. Solve for them rather than guessing.

  • Ink and paper colour — median of the darkest and lightest deciles inside the box. Handles grey annotation text and tinted backgrounds without special cases.
  • Font size — binary-search the point size until ImageFont.getbbox() cap-height matches the measured cap-height to within half a pixel.
  • Tracking — solve (observed_width − natural_width) / (n − 1). CAD text is frequently letter-spaced, and skipping this is what makes re-rendered labels look subtly wrong.
  • Family — render the corrected string in each of a small candidate set and pick the highest normalised cross-correlation against the original crop. Candidates for CAD output: Arial, Helvetica, DIN 1451, ISOCPEUR, Century Gothic, Calibri. Persist the winner per document and reuse it — a drawing almost never mixes families.
Pillow ImageFontcv2.matchTemplatefonttools
S5

Erase the type and repair what it covered

General inpainting is the wrong default here. Plan backgrounds are flat, so a background-colour fill is cleaner and faster than Telea — but linework passing under or beside a label must be reconstructed, or the mirrored plan sprouts gaps in its dimension lines.

  • Mask = dilated text quads ∩ dark pixels, dilation 2–3 px to catch antialiasing halos.
  • Fill each masked region with the modal colour of a 6 px ring around it.
  • Line repair: before erasing, detect long straight runs with morphological opening (kernels (1,40) and (40,1)) plus HoughLinesP. Any line whose endpoints straddle an erased region gets redrawn across it at its measured thickness. This is the step that separates a clean result from an obviously retouched one.
  • Fall back to cv2.inpaint(..., INPAINT_TELEA, 3) for text over hatch patterns or photographic fills, and flag those runs for review.
cv2.inpaintcv2.HoughLinesPcv2.morphologyEx
S6

Flip the canvas

The cheap step, and the one that must be provably lossless: cv2.flip(clean, 1) for a vertical mirror axis, 0 for horizontal, -1 for 180°. Excluded regions — north arrow, scale bar, title block, logo — are lifted out first and re-composited afterwards at mirrored anchors without being flipped themselves.

cv2.flip
S7

Re-render each run at its mirrored anchor

Transform the anchor, normalise the angle for readability, render the string upright, then verify it fits. See §05 for the arithmetic.

  • Anchor on the box centre, not a corner: the re-rendered string is never exactly the original's pixel width, and centre-anchoring keeps it visually where the drafter put it.
  • Fit-to-box guard: after rendering to a transparent layer, measure the actual ink bounds. If they exceed the original by more than 4%, reduce tracking, then size, until they fit. Guarantees a label can never grow into a wall.
  • Collision check: test the rendered alpha against the dark pixels of the flipped drawing. Any overlap is reported as a review item with a suggested nudge along the free axis.
  • Render at 4× and downsample for antialiasing that matches CAD output, or draw with Skia for correct subpixel positioning.
PIL.ImageDraw.textskia-python (opt)
05 · mirror mathematics

Reflect the anchor, negate the angle, then restore readability

Two of the three steps are obvious. The third is the one that decides whether a mirrored plan looks professionally drafted or merely un-backwards.

x′ = W − 1 − x    y′ = y Reflection about the vertical axis of an image W pixels wide. A box (x₁,y₁,x₂,y₂) becomes (W−1−x₂, y₁, W−1−x₁, y₂) — the corners swap, so always recompute rather than mapping each corner in place.
c′ₓ = W − 1 − cₓ The anchor actually used. Centre-anchoring absorbs the small width difference between original and re-rendered glyphs.
θ′ = −θ Baseline angle under reflection, measured counter-clockwise from +x. Reflection also inverts glyph handedness, which is exactly why the run is re-rendered rather than transformed.
θ″ = θ′ + 180°  while  θ′ ∉ (−90°, 90°] Readability normalisation. Horizontal text: 0° → 0°. Vertical dimension text: 90° → −90° → 90°. Text at 30° → −30°, already readable, left alone. Applied to the angle only; the anchor never moves.
Mpage = (−1, 0, 0, 1, W, 0) Route A equivalent — the PDF page CTM. Each text run is then re-emitted with Mrun · Mpage⁻¹ applied to its own matrix, which cancels the reflection for glyphs while leaving vector geometry mirrored. 
# transform/mirror.py — the load-bearing 20 lines

def mirror_run(run: TextRun, W: int) -> TextRun:
    x1, y1, x2, y2 = run.bbox
    bbox = (W - 1 - x2, y1, W - 1 - x1, y2)      # corners swap
    angle = -run.angle_deg                        # reflect the baseline
    while not (-90 < angle <= 90):              # ISO readability
        angle = (angle + 180) % 360
        if angle > 180: angle -= 360
    return replace(run, bbox=bbox, angle_deg=angle,
                   anchor=center_of(bbox))       # never a corner
06 · ui & ux flow

Three screens, and one of them is optional

The drafter's mental model is "flip this sheet". Everything else the tool needs to ask should either have a sensible default or appear only when confidence is low.

Screen 1 — Import

A single window with a drop target and a file picker. Detected input format is shown as a badge (Vector PDF — lossless or Raster PNG — reconstructed) so the operator knows which route ran and how much to trust it. Controls, all with defaults:

  • Mirror axis — Vertical (default) / Horizontal / Both, with a live thumbnail.
  • Language — Danish (default), from the lexicon set.
  • Protect regions — a "mark north arrow / title block" mode that lets the operator drag rectangles the tool must not flip. Remembered per project so it is drawn once for a whole unit-type series.
  • Output — PNG, PDF, or layered PSD; alongside the always-written JSON sidecar.

Screen 2 — Review

Side-by-side synchronised pan and zoom: source left, result right. A QGraphicsView canvas over the result, with every re-rendered run as a selectable item. The review list is sorted by confidence ascending, so the two runs most likely to be wrong are the first things the operator sees rather than something they must hunt for.

  • Click a run: inline edit of the string, size, tracking and angle; drag to nudge the anchor; arrow keys for pixel steps.
  • Flags surfaced automatically — OCR confidence below 0.85, a lexicon snap that changed the string, a collision with linework, an implausible dimension value, a run whose fit-to-box guard had to shrink it.
  • Enter accepts a run, Tab jumps to the next flagged one. A clean plan should be confirmable in under twenty seconds without touching the mouse.

Screen 3 — Batch

Point at a folder, get a table: file, route taken, runs detected, flags raised, output path. Anything with zero flags is written straight out; anything flagged is queued for the review screen. This is where the time actually gets saved on a 40-unit project, and it is why the CLI must exist before the GUI.

# the CLI is the real interface; the GUI is a client of it

spejl mirror plan.png --axis v --lang da -o out/
spejl mirror plans/ --axis v --batch --review-if-flagged --report qa.csv
spejl mirror unit.pdf --axis v            # auto-routes to the lossless path
spejl inspect plan.png --debug out/stages # dumps every S1–S7 intermediate
07 · code architecture

One data structure carries the whole pipeline

Keep OCR behind a Protocol from the first commit

You will change OCR engines at least once — accuracy on Danish diacritics, packaging weight, or licence terms will force it. A three-method OcrBackend protocol (detect, recognise, detect_and_recognise) makes that a one-file change instead of a rewrite, and lets the QA harness score two engines against the same goldens.

09 · edge cases

What will actually break, and what to do about it

Ordered by how much damage each does if it ships unhandled. The first three are the ones that turn a good demo into a rejected tool.

A mirrored plan is a drafting aid, not a validated design

Reflecting a unit can quietly break things a pixel pipeline cannot know about: accessible clearance beside a WC, door approach distances, riser and shaft positions, egress direction. Write "source": …, "axis": …, "generated": …, "route": … into every sidecar, and offer an optional MIRRORED — NOT FOR CONSTRUCTION stamp on the export. Cheap to add now, and it keeps a convenience tool from being mistaken for a compliance one.

10 · acceptance

Five numbers decide whether it works

The team already has a hand-made source/mirrored pair of the two-room unit plan. That pair is fixture #1, and it turns "looks right" into a threshold a build can pass or fail in CI.

MetricHow it is measuredGate
Text recallRuns detected ÷ runs annotated in the golden. The sample plan has 12: six room labels and nine dimensions, with H* as a thirteenth annotation≥ 100%
Character accuracyLevenshtein against annotated strings, after lexicon snap, diacritics counted strictly≥ 99%
Anchor errorEuclidean distance from each run's rendered centre to its expected mirrored centre≤ 3 px
Geometry integritySSIM of the non-text regions against a plain cv2.flip of the source. Proves the pipeline touched nothing it should not have≥ 0.995
IdempotencySSIM of mirror(mirror(x)) against x≥ 0.99

Two qualitative gates sit alongside the numbers, and neither can be automated away:

  • The zoom test. At 100% zoom, a drafter who did not run the tool cannot point to which labels were re-rendered. Erase scars and font mismatches both fail here, and both pass every metric above.
  • The unaided test. A colleague with no briefing mirrors a plan and confirms the result in under a minute. If they hesitate over the review screen, the flag ordering is wrong, not the operator.

Grow the golden set to roughly fifteen fixtures across the real variation the office sees: vector and raster, 150 and 300 dpi, Danish and English labels, a sheet with a title block and north arrow, one JPEG, one screenshot, one plan with area figures, and one deliberately awful scan that the tool is expected to refuse rather than mangle. Refusal is a passing outcome and should be tested as one.
